### 2.2 规则清单与生效边界

每只基金、份额类别、渠道分别建立不可变规则版本。`channel` 固定为 `ant_fund_alipay`，

| 必填规则 | 证据要求与未知处理 |
| --- | --- |

| `holding_period_basis/lot_order` | 确认日起算、赎回计费截止日、自然日或工作日、先进先出依据 |

| `source_url/evidence_ref/published_at/effective_from/effective_to/checked_at` | 链接、条款定位、受控证据摘要或文件哈希；禁止只保留搜索摘要 |

规则分为 `verified`、`incomplete`、`expired`、`conflict`。生产模式非 `verified` 不产生新订单；隔离测试只允许第 2.5 节固定的 fixture 规则。
静态条款沿用至修订；动态开放状态、暂停与限额每个运行日重新核对，`valid_through` 只到当日。
没有自动可靠渠道数据时，允许人工核对后导入当日证据，未核对则跳过，不把人工前置条件说成完全无人值守。
不抓取支付宝登录凭据，不连接支付或交易接口。

规则导入须校验字段完整、日期区间不重叠、金额与份额非负且精度正确；`null` 仅表示未知，不表示零费用或无限制。
区间为左闭右开：`effective_from` 当日生效，`effective_to` 当日不再生效，续期版本正接在旧版本的结束日上。
订单只带基金代码，所以同一代码的全部版本必须共用渠道与份额类别；导入时拒绝同代码的歧义版本：
渠道或份额类别不一致、生效日相同，或声明了结束日的旧版本被新版本从中间穿入。
`effective_to` 为空表示「生效至被后续版本取代」，不算与后续版本重叠，因此正常的修订路径不会阻断该基金。
版本不可覆盖，修订只能新增更晚的 `effective_from`，不能改写或撤销已导入版本；选取时按生效日取最新一条。
若库中仍出现绕过导入的歧义版本，选取按 `rule_conflict` 阻断该基金，不静默挑一条执行。
待处理订单绑定申请时规则；随后公告若明确影响已受理申请，追加事件并暂停相关结算等待核对，不覆盖旧版本。

## 4. 账本与金额

### 4.1 精度与资产

资金、费用、净值、份额通过十进制字符串传入，使用 Python `Decimal` 计算，SQLite 存规范十进制 `TEXT`。
禁止 JSON number、科学计数法、NaN、Infinity、负申购额和零份额；金额最多两位，份额最多四位，净值最多八位，
源精度超界直接报错，不能先转 float。计算精度至少 28 位。
金额按 `ROUND_HALF_UP` 到 0.01；份额按基金规则量化，首个隔离样例使用 0.01 份四舍五入。
基金实际精度与取整方式未核验时不可运行；现有真实份额四位存储不代表基金成交采用四位。

| 余额 | 定义 |
| --- | --- |
| 可用现金 A | 可再次申请的人民币现金 |
| 冻结现金 F | 已受理未确认的含费申购额，取消或失败时原额退回 A |
| 赎回应收 R | 已确认赎回净额，到账前不可买入 |
| 分红应收 D | 已登记且除息生效的现金红利，发放前不可买入 |
| 持仓价值 H | 已确认份额（含赎回冻结份额）乘所用官方净值；确认赎回后扣除该份额 |
| 总资产 V | `A + F + R + D + H`，冻结及应收均只能计一次 |

申购等待期间按冻结现金计值，不虚构份额。赎回待净值期间仍计持仓，确认后转为应收。
费用后累计收益 `V - 200000.00`，收益率除以 200000；没有额外外部入金或出金。
申购、赎回、分红到账是内部划转，不计收入或外部现金流；费用在确认时扣除，净值内扣管理费、托管费、
销售服务费不重复从现金扣费。持仓成本按批次记录，用于赎回费龄与已实现收益，不充当资产估值。

### 4.2 估值与风控

账户每日 13:50 及每次结算后生成观察快照；决策在事务内使用最近可用完整快照和最新余额再校验。
每只持仓保留独立 `nav_date`，混合日期总资产是「截至观察时刻的最近官方净值资产」，不伪称同日 NAV。
所有持仓及目标基金必须有正值净值，且不晚于当时已应披露的最近净值日；是否逾期由基金规则与日历推导。
已应披露但缺失、规则未知、净值冲突或日历超覆盖即 `incomplete`；可展示旧值但不更新高点、不生成买单。
现金账户无持仓时 V 完整，目标基金仍须有可核验净值与开放规则。

单只占用 `E_i = 当前持仓价值 + 该基金待确认买入含费额`；归组占用为该指数组 E 之和。
拟买金额 B 要求 `(E_i+B)/V <= 25%`、已核验指数组 `(E_group+B)/V <= 40%`；
V 已包含冻结现金，不能再加待处理买单。未确认卖单不得提前释放仓位，已确认应收不作为可用现金。
同一批按代码顺序逐笔预留，再校验下一笔；被动上涨超限只阻止加仓，不强制卖出。

初始高点 200,000.00；每个完整观察快照更新 `peak=max(peak,V)`，`drawdown=1-V/peak`。
回撤达到 15% 即锁定 `risk_paused`。最大回撤为完整快照回撤最大值，显示观察区间、完整记录数及缺失数，
不称盘中最大亏损。费用、取整差额与现金均计入 V。
恢复须人工动作、有完整数据、回撤低于 15%、规则有效；不能重置高点以绕开回撤。
仍在触发线下时只能保持暂停，若要变更阈值需另行修改方案，不提供静默豁免。
手动暂停可直接恢复但仍经过同样校验；账户归档不能恢复交易。

## 5. 状态机与结算

订单拒绝发生在冻结前，保存 `rejected` 和原因；策略无可执行金额保存运行项 `skipped`，不造零额订单。
申购：`accepted → awaiting_nav → awaiting_confirmation → settled`。
赎回：`accepted → awaiting_nav → awaiting_confirmation → awaiting_payment → settled`。
已取得适用净值仍须等规则规定的确认日；若已到确认日可在一次事务中经过相应状态。
订单事件逐条保留，展示状态可合并为「待净值」「待确认」「待到账」「已完成」。

| 转移 | 账本动作与条件 |
| --- | --- |
| 受理申购 | `A -= B; F += B`，绑定规则、快照、周期和幂等键 |
| 受理赎回 | 从可售批次按核验的顺序冻结份额，持仓总份额暂不减少 |
| 撤销 | 仅受理后且早于规则撤单截止、尚未确认；释放冻结，状态 `cancelled` |
| 业务失败 | 明确的不受理或确认失败证据才可 `failed`，全额释放冻结；已确认订单不回滚成失败 |
| 数据或技术失败 | 保持原状态，另记错误与重试次数；净值延迟不自动退款、不换日期 |
| 申购确认 | F 减含费额，增加批次份额和净成本，记录费用与取整差额 |
| 赎回确认 | 扣冻结份额及其成本，R 增净到账额；费用按各批次持有期计算后汇总 |
| 赎回到账 | 到账规则和日期完整且已到时点，`R -= proceeds; A += proceeds` |

初始规则验证通过才能受理。已受理后证据冲突设置 `blocked_reason`，保留冻结和资产，不重复收费。
停机恢复时按事实发生日和当前处理时刻分别记账；`confirmed_at/paid_at` 为实际处理时刻，
`effective_date` 为模型规定的归属日期，不能伪造当时进程已执行。

首版部分执行只发生在受理前：计划 500.00、已知剩余额度 200.00，生成一笔 200.00 的订单，
运行项保留未执行 300.00 与 `daily_limit` 原因。受理后整笔确认或整笔失败，
不支持摆动定价、比例配售、巨额赎回部分确认；遇此类公告停止新申请，已有订单等待明确结果，不假定全额成交。

### 分红与净值更正

仅现金分红。保存公告 ID、每份金额、登记日、除息日、发放日、税费与权益规则版本。
按登记日已确认且享有权益的批次锁定份额，已确认赎回是否享权以公告为准；缺证据不猜。
除息日 D 增应收，采用对应除息净值；发放日 D 转 A。公告未完整时相关资产快照标不完整并暂停买入，
不把除息跌幅误判为已核实亏损。重复公告 ID 不重复入账。红利再投资、拆分或合并首版不自动处理，
遇到后阻断相关基金结算与完整估值，待扩展契约，不静默忽略。
已用于成交的净值后来更正时，不覆盖旧成交；锁定受影响账户新增买入，保留旧版与更正版及差异，
通过人工审定的冲正事件处理后恢复。首版不提供一键自动重算全部历史。

### 幂等与事务

幂等键作用域为账户 + 操作类型，永久保留。同键同规范化请求返回原结果；同键不同请求 `409`。
策略周期唯一键为账户 + 北京时间计划日期，不含策略版本，防止改版本重跑同一周。
订单键派生自周期与基金代码；首版每周期每基金一笔，顺序固定。

网络与解析在事务外完成。`BEGIN IMMEDIATE` 内重查账户暂停、版本、周期状态、限额累计、现金、份额、仓位；
插入订单、事件、冻结与周期结果一起提交。结算状态迁移、账本和批次变更同一事务提交。
写锁超时返回可重试错误，不返回成功；重试沿用原键。进程锁仅减少争用，唯一约束与事务才保证正确性。
跨库读取失败不会产生模拟订单；已有完整快照可用于其绑定订单结算，不能伪造新的数据获取成功。

```text
  持仓列表 → 份额、官方净值日、价值

  阶段 7：运行记录 → 本期逐基金结果 → 对应订单
  阶段 7：暂停新增买入 / 恢复
```

手机订单详情采用现有全屏 Drawer，展示申请、净值归属、确认、到账四类日期，以及金额、费用、份额和原因。
空日期显示「—」，缺失或冲突在对应字段旁显示状态，不新增整页解释性 banner。
阶段 6 无账户时仅提供「建立模拟账户」动作；不显示虚构资产或空 AI 入口。
运行项没有订单时直接显示跳过原因；技术失败显示失败和可重试状态，不显示成交。
暂停按钮不二次确认，点击等待服务端提交后更新；失败保持原状态并在按钮附近显示错误。
恢复被回撤或数据阻止时显示具体阻止项。重置不放在首页，不做移动端手动申赎表单。
返回保留筛选、分页和滚动位置；关闭 Drawer 后焦点返回原行。390/430 px 无横向溢出，金额和长名称不挤压日期。

## 10. 备份、恢复与重置

模拟库通过 SQLite 在线备份获得一致快照，不能只复制活跃 WAL 的主文件。备份包含规则、快照、
幂等键、账本、周期和 schema 版本；主库另行备份，不承诺跨库同一事务时点。
恢复时停止模拟写入与调度，校验 schema、完整性及账本重放，显式核对目标路径；
恢复后保持暂停，核对备份之后是否有已记录周期，过去窗口一律不补单。

「重置」语义定为归档旧实验并新建账户，不删除、清空或覆盖原历史。仅本地管理命令提供，
展示旧账户 ID、待处理单数与新实验 200000.00 元，要求独立确认。
有待结算、待到账、分红应收时拒绝归档；先暂停买入，处理完成再归档。
初始化和归档/新建在同一模拟库事务中，保留操作者、确认时刻、原因和前后账户 ID。
不触及真实数据库，也不把新账户期初入金计入旧实验收益。备份恢复覆盖文件本身须另获操作确认。

周期状态为 `running/completed/partial/failed/missed`；`completed` 允许全部正确跳过，
`partial` 指部分基金技术失败，`failed` 指整轮技术失败。每项另有 `accepted/skipped/failed`。
过期重启可补记 `missed` 运行记录，不能补建订单；重试只处理未落定项，已经接受的订单不重新生成。

指标：费用后资产变化按第 4 节；现金占比 `(A+F)/V`，应收另列；
累计换手定义为 `(累计申购净额 + 累计赎回毛额) / 完整日终资产的算术平均值`，不除以 2、不年化，
无完整日终样本时为空；运行区间、完整样本数、缺失数及总费用同时提供。
该口径是本产品描述指标，不宣称基金行业标准换手率或策略有效性。
阶段 7 须增加每日 23:30 的日终观察快照，仍以当时已知官方净值为准，不倒填后来披露值。

上线门槛：规则包可用、P0-B 的真实采集与备份恢复证据齐备、适用年份日历齐备；
手机远程还需 P0-A。全部跳过是正确结果，但无法替代成交结算验收；等待净值或到账则标「待真实时段验收」。
