# 移动端响应式计划

状态：阶段 1 已完成（2026-09-04）。浏览器验收已完成；真机安全区、触摸滚动和软键盘检查
未覆盖，作为剩余风险保留。

本计划覆盖 `/valuation`、`/holdings` 和 `/import`。目标是在手机端完成与桌面端相同的核心任务，
不是把桌面界面按比例缩小。

阶段 3 已把 `/import` 调整为「持仓录入」，截图选择、候选修正、差异确认和批量写入沿用本计划
的断点、触控区域和安全区约束。

## 断点与页面框架

- 不大于 768 px：手机布局，隐藏左侧 rail，使用底部主导航。
- 769–1023 px：平板布局，允许使用折叠 rail。
- 1024 px 及以上：保留现有桌面工作台。
- 手机正文预留底部导航高度和 `env(safe-area-inset-bottom)`，固定元素不得遮挡内容。
- 页面本身不得横向滚动；只有行情条和确实无法压缩的数据区域可以局部横向滚动。

底部导航固定显示「估值」「持仓」「录入」三个入口。当前项需要有文字和视觉状态，单个触控区域
不小于 44×44 px。

## 估值页

- 页头保留页面标题、数据状态和刷新操作，次要说明压缩或换行。
- 主指标占据整行，其余指标按两列排列；数值不得重叠或依赖缩小字号硬塞。
- 市场行情使用横向滚动条，单项保留名称、价格、涨跌、交易阶段和更新时间。
- 基金列表在手机端使用无外框双行列表：
  - 第一行显示基金名称和盘中涨跌。
  - 第二行显示基金代码、今日收益和数据状态。
- 排序和筛选保留，但不并排堆放所有桌面控件。
- 基金详情使用全屏面板，保留明确关闭按钮、焦点管理和内部滚动；不增加拖拽关闭手势。

## 持仓页

- 持仓使用紧凑列表，优先展示基金名称、代码、持仓金额和收益信息。
- 新增和编辑使用全屏表单，字段纵向排列。
- 行操作不得依赖 hover；编辑和删除入口需要直接触达。
- 删除继续使用明确确认，不改变现有数据安全语义。

## 录入页

- 截图选择、候选核对、变更确认和完成按纵向步骤排列。
- 相册、拍照和主要操作按钮在窄屏下占满可用宽度。
- 候选使用纵向卡片编辑代码、名称、金额、可选份额和成本；低可信字段不依赖 hover。
- 替换全部的待删除项默认展开，确认控件和删除清单保持相邻。
- 识别和写入错误紧邻当前步骤，失败后保留可修正内容。

## 通用交互

- 主要触控区域不小于 44×44 px。
- 正文和主要数据不使用小于 12 px 的字号；核心名称和数值以 14 px 以上为基准。
- 焦点状态、键盘操作和 `prefers-reduced-motion` 行为继续有效。
- 加载、空数据、部分失败和提交失败状态不得因移动布局而消失。
- 不增加自定义下拉刷新、复杂手势、PWA、推送通知或与响应式无关的视觉重构。
