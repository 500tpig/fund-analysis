# 估值页展示改版

状态：第一批已实施并通过浏览器验收（2026-09-26）；后续任务见 `docs/project-roadmap.md`。本文件只约束 `/valuation` 的信息架构与展示，
不改变收益口径、刷新策略和三页平级结构；与 `docs/mobile-responsive-plan.md` 冲突时，
估值页以本文件为准，其余页面仍按原计划执行。

## 问题

- 汇总与每行收益只认北京时间今天。周末、节假日和交易日盘前，汇总区显示多块「暂无」，
  列表的「盘中涨跌 / 预估收益」全部为空，而最近交易日的官方净值和涨跌幅已在数据里。
- 手机上第一只基金之前约 515 px（按 CSS 推算），首屏只能看到 2～3 只；时间与覆盖信息在
  页头、汇总提示、刷新状态行重复三次；手机行的次要文字为 10～11 px，低于 12 px 的下限。
- 手机上市场行情被排到列表之后，实际看不到大盘。

## 原则

1. 页面任何时刻都展示一个有数的「展示日」，不出现整块「暂无」。
2. 先看赚亏，再看每只基金，其余信息降级。
3. 正常不说话，异常才标记：只有日期落后、数据延迟、无估值等情况在行内出现标记。
4. 展示口径沿用现有监控口径（当前金额 × 涨跌幅的情景值），不进入可核对收益，
   页面保留「非实际结算收益」说明。

## 展示日契约

后端在 `summary.today` 增加 `display_session`：

```jsonc
{
  "date": "2026-09-24",          // 展示日
  "is_today": false,
  "mode": "today",               // today | latest_official
  "profit": -2042.30,            // 可为 null（例如无任何净值）
  "rate_pct": -1.26,
  "count": 17,                   // 计入合计的基金数
  "total": 19,                   // 基金总数（不含现金）
  "amount": 158000.00,           // 计入部分的基准金额
  "official_count": 17,
  "estimate_count": 0,
  "updated_at": "2026-09-24T21:10:00+08:00"
}
```

选择规则：

- `summary.today.monitoring.count > 0` 时为 `mode=today`，数值与 `monitoring` 一致。
- 否则为 `mode=latest_official`：展示日取所有基金行 `nav_date` 中不晚于今天的最大值；
  只合计 `nav_date == 展示日` 的行。单行金额优先取 `fund_official_daily_profit` 中
  `(code, 展示日)` 的记录，与详情「官方日收益」一致；没有记录时用 `amount × daily_return_pct / 100`，
  沿用 `profit_from_rate` 的舍入。
- 没有任何可用净值时 `profit=null`、`count=0`，`date` 取最近国内交易日。

每个基金行增加 `session_profit`：

```jsonc
{
  "amount": -83.18,             // 可为 null
  "return_pct": -1.40,
  "return_date": "2026-09-24",
  "kind": "official_measurement", // official_measurement | estimate | null
  "in_session": true            // return_date 是否等于展示日（是否计入 display_session）
}
```

- `mode=today`：有 `monitoring_profit` 时取它（`in_session=true`）；没有时回退到该行最近官方净值日收益，
  `in_session=false`，使交易日内的 QDII 等行仍能显示最近一日数值和日期标记。
- `mode=latest_official`：取该行最近官方净值日的收益（规则同上），日期早于展示日的行
  （如 QDII）照常显示数值，但 `in_session=false`，不计入合计。
- 现金行为 `null`。
- 没有任何净值且交易日历未覆盖当前年份时，`display_session.date` 为 `null`，不猜测日期。

## 估值页布局

手机（≤768 px）自上而下：

```
基金估值                      09-24 收盘   ⟳
09-24 当日收益 · 已更新 17/19          ⓘ
-2,042.30    -1.26%
总资产 160,450.21        持有收益 -8,xxx.xx
中证全指 -1.86% · 黄金 -0.86% · 纳指 +0.48%   ← 单行横滑
全部 19   延迟 2   无估值 1            🔍
基金                 金额          当日收益
财通品质甄选混合C    5,939.16        -83.18
024481                               -1.40%
```

- 页头：标题 + 一行状态（展示日与阶段，如「09-24 收盘」「盘中 14:32」「更新中 12/19」），
  刷新按钮在手机上为 44×44 图标按钮并保留 `aria-label`。原刷新状态行并入页头状态，
  `aria-live` 保留。
- 汇总：主值为 `display_session.profit` 与 `rate_pct`，标题随 `mode` 变化：
  `today` 时为「今日收益」或「今日预估」（有估值参与时），`latest_official` 时为「MM-DD 当日收益」；
  覆盖不全时显示「已更新 count/total」。次值为总资产与持有收益（`total_holding_profit`）。
  删除「今日官方测算」「未披露盘中预估」两块，官方/预估构成放入主值下的一行小字或 ⓘ 说明。
  「非实际结算收益」放入 ⓘ，手机上可点开阅读，不直接隐藏。
- 行情：放在汇总之后，手机单行横滑，单项只保留名称、涨跌幅和交易状态点；桌面为一行紧凑条。
- 工具栏：手机一行，筛选只显示「全部」和数量大于 0 的异常项并带数量，搜索收为图标，
  点开后展开输入框；桌面保持现有搜索与筛选，筛选项同样带数量。
- 列表：手机三列「基金 | 金额 | 当日收益」，表头可排序（基金、金额、当日收益）。
  行高 56～64 px，所有文字不小于 12 px。第二行只显示代码与异常标记。
  桌面表格为「基金 | 持仓金额 | 当日涨跌 | 当日收益 | 持有收益」，取消「数据状态」列。
- 组合分析：保留在估值页，移到列表之后，默认折叠。

行内标记（只在异常时出现，最多两个）：

| 条件 | 标记 |
| --- | --- |
| `session_profit.return_date` 早于展示日 | 「MM-DD」 |
| `display_session.mode=today` 且盘中估值过期（`estimated_status=stale`） | 「延迟」 |
| `display_session.mode=today`、交易时段内该行无盘中估值 | 「无估值」 |
| 展示日合计同时含官方和预估时的预估行 | 「估」 |

`mode=latest_official`（周末、节假日、盘前）时不显示「延迟」「无估值」：此时展示的是官方净值，
旧的盘中估值不影响阅读。

完整状态（来源、时间、披露状态）保留在详情与桌面行的 `title` 中。
