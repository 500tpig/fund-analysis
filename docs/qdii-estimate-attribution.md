`today_profit.assess_estimate_basis` 的保守收益判断没有被对账流程调用。

判断：不同来源给出不同估值本身可以合理，不能据此判定哪一个更准。裸字符串时间排序是实现缺陷，
两表保存策略不同解释了本次现象；原新浪响应缺失，无法完整还原来源切换前后的全部采集过程。

## 6. 已确认的最小实施方案

推荐复用现有 provider、SQLite、日样本表与官方存档，不新增估值模型、依赖、来源调用、UI 或采集任务。
现有唯一键和字段不足以同时保留两个来源、跨午夜会话及同一报价时间的来源修订，**需要 schema 变更**。

### 6.1 schema、API 和历史影响

建议重建 `fund_estimate_daily_accuracy` 的唯一约束，保留原有 id、样本和结果列，新增：

- `evidence_json`：存完整的标准化估值快照及来源相关原字段，包括 previous_nav、
  previous_nav_date、source_url、真实 fetched_at、原报价时间、选中点、窗口和模式标记。
- `attribution_reason`：记录不能归属或不能对账的具体原因；海外默认未知，不能默认成功。
- `estimate_fingerprint`：标准库哈希，对报价及基准相关内容去重，不纳入 fetched_at 等采集元数据。

候选记录唯一键改为 `(code, estimate_source, estimated_at, estimate_fingerprint)`。
同源同报价同内容的重复采集不新增候选；同时间的不同来源或内容修订均保留，不互相覆盖。
同时间修订若缺少明确的来源修订顺序则标记歧义，不自动选对误差更小的一条。
仍只保存每次现有采集实际选中的点，不展开新浪全部分钟数组，也不额外采集多源。

历史行只复制现存字段，新增证据为空；不得用当前最新表补进历史证据。迁移隔离验证后才可提出
生产变更，生产迁移仍需另行确认。原始 `estimated_at` 不改写；时间比较使用单独解析后的时间。
时区未核实的海外来源不得强行附上北京时间来确认归属。

API JSON 字段不新增，UI 不改动。摘要查询必须同步调整：已对账数按唯一净值日、来源选定样本
统计；待对账数按观察日、来源去重，不能因保留更多候选而膨胀。历史国内只有单条候选时保持
原统计结果；基准校验失败的记录不再作为可靠误差样本，这属于纠正统计口径，需一并确认。

### 6.2 归属、选样和基准

1. 归属解析位于来源标准化与存储之间，保留原值。只有来源明确目标日，或已核实的时区、
   市场会话到基金净值日契约齐全时才填目标日。当前没有通过的海外规则；先实现未知原因与留证，
   不编造一个海外成功来源。国内保留明确规则，补北京时间及交易日校验。
2. 日期确认后，还须证明是目标会话的收盘候选。盘中点可留档，但不进入收盘误差统计；
   同一目标日、同一来源只选一条最终可靠候选。未知窗口、模式切换、收盘后补发或来源修订
   无法解释时，保持未知，不按最大时间机械认作最终估值。
3. 核对目标日的上一官方净值日、来源前值日期和前值数值，并校验估值净值与来源涨跌幅的
   数值一致性。容差考虑来源净值和百分比精度；数值自洽只是一项必要检查。
   缺少收益期间、币种或分红／拆分口径证据时不对账。沿用 `today_profit` 已有基础校验，
   不复制一套近似逻辑；它目前按「今天」判断归属的部分不能直接用于历史对账。
4. 来源原始涨跌幅保持不变；基准不一致时记录原因，不通过另一个官方前值重算来制造可比收益。
   官方值按目标净值日查询已有 `fund_official_daily_profit` / `fund_nav_history`，只读取净值与
   官方涨跌幅，不将持仓金额带入估值误差。不具备完整日涨跌幅和前值证据时保持待对账。
5. 官方延迟披露时等待同一目标日，不能改配最新日；更正时重新校验和计算已有配对。
   最新表防止同源旧报价倒退，跨来源无可比时间时不按字符串决定优劣；最新展示与对账候选分别留证。

原因至少区分：`source_date_unverified`、`source_timezone_unverified`、`source_mode_unverified`、
`not_session_close`、`quote_revision_ambiguous`、`baseline_missing`、`baseline_mismatch`、
`official_missing`、`legacy_evidence_missing`。原因写入数据和报告，不增加 UI 提示。

### 6.3 涉及范围与完成标准

实现范围：`fund_data.py` 的来源留证、`web/app.py:_refresh_funds` 的候选入库与对账调用、
`web/storage.py` 的迁移／去重／摘要／历史官方读取；如复用校验需要调整 `today_profit.py`，
仅拆出历史日期也可用的现有纯校验。相关调用与测试包括 `test_fund_data.py`、
`test_web_storage.py`、`test_collection.py`、`test_web_api.py`、`test_today_profit.py`。
保留已有未提交改动，不引入前端改版或模拟业务变更。

隔离数据验收必须覆盖：

| 情况 | 预期 |
| --- | --- |
| 跨午夜、周五至周六、夏令时切换 | 保留原报价时间；仅经核实会话可归属，不简单减一天；一个净值日不重复计数 |
| 周末、国内与海外休市不同步 | 未核实基金净值日历时保持未知；不能用国内日历替海外填日期 |

| 前值日或前值数值不同、净值比不一致、分红口径未知 | 不配对，原因明确，原涨跌幅不改 |
| 凌晨收盘后又采到当晚盘中点 | 收盘候选仍保留；盘中点不覆盖该目标日结果 |
| 境内正常收盘与官方更正 | 正常对账；合理去重；更正重算，既有正常统计不回归 |
| 旧库迁移 | 行数、原字段与未知状态保留，不以当前快照补历史证据 |

报告逐条列来源、真实报价时间、归属日、预估涨跌幅、官方涨跌幅、误差及未知原因。
误差为「预估减官方」，单位为百分点。分别报告平均绝对误差、最大绝对误差、方向一致率。
方向一致率按三态符号（正／零／负）相同的比例计算，报告分母；零样本显示不可计算。
合并统计不得把同一来源同一净值日的多个采集点当作独立样本。
