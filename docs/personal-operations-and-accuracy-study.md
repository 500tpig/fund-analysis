## 1. 目标与当前能力

目标是构建以手机为主要使用端的个人基金决策辅助工具：观察基金状态，理解变化，记录操作，
结合新闻与 AI 学习金融概念，形成可复核的买入、持有、卖出或继续观察计划，并在模拟舱验证。
定时执行固定策略不依赖 AI；AI 可以解释证据或提出候选计划，不能因生成了结论就改变真实持仓。

当前已有 Vue SPA、官方净值与盘中估值、跨市场日期处理、持仓与截图录入、组合结构和风险分析。
`ocvps` 部署情况以 [README](../README.md) 为准。本次未连接远端重新验收；AI、新闻、操作日记、
模拟舱及策略执行均为规划能力，不属于当前已交付功能。

数据来自本地 `data/fund_analysis.db` 的 `fund_estimate_daily_accuracy` 表，本次只读复算。
它不是远端运行库的当前统计，也不是账户实际收益核对。

| 项目 | 数值 | 口径 |
| --- | --- | --- |
| 留存记录 | 136 条 | 按基金代码与观察日期留存，不是所有盘中时点快照 |
| 可计算误差的已对账记录 | 39 条 | 2026-09-03、09-04、09-07、09-08，共 4 个交易日 |
| 已对账来源 | `eastmoney_fund_core_diy` | 全部 39 条均来自此来源 |
| MAE | 0.3097 个百分点 | 每条估值涨跌幅与官方涨跌幅之差的绝对值，再取均值 |
| 样本最大绝对误差 | 1.93 个百分点 | 011452，2026-09-07；不是未来误差上限 |
| 每只已对账基金的样本数 | 3～4 条 | 其余基金没有有效误差样本，不参与均值 |
| 来源估值时间 | 对应日期 15:00–15:30 | `estimated_at`，不等同于系统采集时间 |

[存储实现](../src/fund_analysis/web/storage.py) 的 `upsert_estimate_daily_sample` 在同一
`(code, observed_date)` 下只保留来源时间更晚的记录。这一机制本身不能保证保存的是收盘样本；
本次来源时间范围由数据库查询得到。以上数字只描述这 4 天的收盘附近留存值，不能代表全天盘中精度、
其他来源或未来误差分布。未对账记录不能按零误差处理，亦不能假设它们与已对账记录具有相同分布。

持仓披露滞后、现金仓位、市场变化和来源算法可以列为待核验因素，误差表不能单独证明这些归因。
不能将其中任何基金的低 MAE 表述为「估值等同结算净值」。

复算查询如下，须通过 `sqlite3 -readonly data/fund_analysis.db` 执行：

```sql
SELECT COUNT(*) AS total, COUNT(error_pct_points) AS error_samples,
       AVG(ABS(error_pct_points)) AS mae_pp,
       MAX(ABS(error_pct_points)) AS max_error_pp
FROM fund_estimate_daily_accuracy;

SELECT observed_date, estimate_source, COUNT(*) AS samples,
       MIN(estimated_at) AS first_source_time,
       MAX(estimated_at) AS last_source_time
FROM fund_estimate_daily_accuracy
WHERE reconciled_at IS NOT NULL AND error_pct_points IS NOT NULL
GROUP BY observed_date, estimate_source;

SELECT code, COUNT(*) AS samples,
       AVG(ABS(error_pct_points)) AS mae_pp,
       MAX(ABS(error_pct_points)) AS max_error_pp
FROM fund_estimate_daily_accuracy
WHERE reconciled_at IS NOT NULL AND error_pct_points IS NOT NULL
GROUP BY code;
```

## 3. 操作日记与收益核算

### 真实交易事实

官方净值披露不等于个人订单确认。[现有录入契约](holdings-entry-plan.md) 禁止把
`amount / official_nav` 或 `amount / estimated_nav` 写成已确认份额。
申请时间、适用净值日期、确认日期和现金收付日期具有不同含义；具体以基金及销售渠道规则和交易凭证为准。
含费支付额、净申购额、赎回到账额也不可混用。未确认、撤销、失败的申请不属于已确认操作。

首版日记建议只记录人工核对的已确认买卖。字段含义先定稿，再决定 SQL；本稿不预建表。

| 内容 | 建议语义 | 实施前待决事项 |
| --- | --- | --- |
| 基金 | 已核对代码及份额类别 | 已清仓基金仍可记录，不能依赖当前持仓行存活 |
| 日期 | 分别保存申请日期与已确认的净值归属日期；未知留空 | 哪项必填、如何补录，以真实凭证样例确定 |
| 买入金额 | 建议记录实际含费支付额 | 与费用分栏展示的关系 |
| 卖出金额 | 建议记录实际净到账额；未到账留空 | 是否首版另存到账日期 |
| 成交份额 | 人工输入的确认份额，可空，不反推 | 沿用现有十进制字符串方式，不新增 `shares REAL` |
| 理由与标签 | 个人记录，可编辑 | 事后补记不能当作事前预测证据，保留创建及更新时间 |

日期、代码、类型、金额和份额须校验后保存，不能把「不推算」理解为任意输入直接入库。
金额边界沿用现有 `Decimal` 解析规范；最终存储与 API 变更在该阶段定稿。
记录、编辑、删除日记均不更新真实持仓金额、成本或收益。

走势图优先按已确认净值归属日打点。该日期缺失或没有对应净值点时，在操作列表展示记录，
不擅自挪到下一个交易日，也不把申请日标记伪装为成交净值。手机通过点击打开详情，不依赖悬停。

### 日记不是完整账本

零散日记用于备忘和复盘，不能独立支撑完整账户收益。完整交易账本用于重建历史持仓，
需要交易、费用、分红、份额变动等完整事实；它与「计算一个期间的 XIRR」的数据要求不同。

计算明确期间的组合 XIRR，至少需要同一核算边界下的可靠期初价值、期间外部现金流及日期、
期末价值。若这些资料能够独立取得，不必先重建每笔内部交易；还须处理无有效解、多解等情况。
卖出后的钱若留在组合现金账户内，不属于组合外部流出；单基金与组合不能共用未经区分的现金流。
依据：[Portfolio Performance 的资金加权收益说明](https://help.portfolio-performance.info/en/concepts/performance/money-weighted/)。

TTWROR 剔除外部现金存取对回报计算的影响，但不自动等于「选品能力」；XIRR 也不能单独证明择时能力。
依据：[时间加权收益说明](https://help.portfolio-performance.info/en/concepts/performance/time-weighted/)。

操作之后的标的涨跌不等于操作贡献，也不能简单等同于市场 β。未来若增加 20/60 日追踪，
须确定净值日序列、分红口径、费用、观察期不足和对照策略，先展示描述统计，不直接比较标签胜率。
**日记首版只含事实记录、理由与标签、历史走势打点；不含区间追踪、XIRR 或策略胜率。**

## 5. AI、计划和模拟舱的职责

| 能力 | 输入与产出 | 边界 |
| --- | --- | --- |
| 基金状态 | 已核验净值、回撤、风险、集中度、数据日期 | 涨跌不直接等于便宜或昂贵；没有估值数据就不生成估值分位 |
| AI 教学 | 当前指标与可查证知识，解释概念、例子和局限 | 学习内容按需打开；模型知识不是当前新闻或确定事实来源 |
| 新闻分析 | 公告、新闻原文链接、发布时间、获取时间及基金关联证据 | 区分事实与推测；没有底层持仓证据不生成精确受益比例 |
| 买卖计划 | 个人目标、期限、可用资金、风险约束与已有证据 | 给出买入、持有、卖出或观察候选及成立/失效条件，真实交易人工执行 |
| 模拟舱 | 独立虚拟资金、模拟订单、明确成交与费用规则 | 不写真实持仓；模拟成交允许按已定义模型计算，不能冒充真实确认份额 |
| 固定策略 | 明确记录的参数、条件及版本 | 相同输入结果可复现，执行不依赖 AI；用户授权拟定模拟参数，不能据此推断真实风险承受能力 |
| 定时分析 | 已启用计划、数据快照和运行预算 | 可只运行规则；AI 为可选分析步骤，不获得真实下单能力 |

当前路线已调整为：先完成独立模拟账本与结算，再运行一种固定周期定额策略，最后接 AI 自动模拟对照。
首版策略不调用 AI；后续 AI 只提交结构化提案，复用相同代码校验资金、份额、仓位和成交规则。
手动暂停与检查记录必须可用；真实交易始终人工执行，不把完整真实交易账本作为模拟前置条件。
购买渠道为支付宝，初始虚拟资金为 200,000 元人民币现金。用户授权拟定其他模拟风险参数与预算，
当前默认值及尚缺输入统一见 roadmap，不在研究文档维护第二份参数表。这些参数不代表真实账户风险授权。
场外基金模拟需区分提交时刻、适用净值日、净值可得时刻及赎回到账；不得先看到当日收盘净值再
倒填当日截止前买单。费用、申赎限制、分红、节假日与份额取整规则缺失时，应限制支持范围，
不能静默假定免费、即时到账或全部可成交。首版支持哪些基金，由模拟阶段的专项方案确认。

历史回测作为后续候选：只有具备当时可获得的数据与规则才可声称无未来信息；新闻按当时发布时间
截断仍不能排除模型训练知识泄漏，因此 AI 历史回放不得包装为无泄漏投资业绩。优先保留前向模拟记录。

具体阶段、依赖、手机验收和服务器任务见 [产品路线](project-roadmap.md)，本稿不维护第二套排期。

## 6. QDII 优先、分析框架与新闻来源

用户已确认：首版海外范围为境内购买的 QDII，每天评估一次，以中长期持有为主。
分析与模拟均须首先覆盖这些基金；不能以延期支持海外基金来降低首版难度。

建议按以下层次组织分析，暂不合成为一个缺乏校准的「买卖评分」：

| 层次 | 要回答的问题 | 所需依据 |
| --- | --- | --- |
| 数据 | 哪些信息在决策当时已经可得 | 来源时刻、净值日、发布时间、获取时间、缺失与冲突 |
| 投资范围 | 这只基金实际投资什么、跟踪什么 | 基金合同、官方基准、定期报告及其报告期；名称不足以证明持仓 |
| 市场 | 对应资产的走势、回撤与风险如何 | 匹配的净值和基准序列；估值指标仅在有可靠口径时使用 |
| 海外因素 | 汇率、利率和事件可能通过什么渠道影响基金 | 币种、汇率时点、官方数据、新闻及可核验的资产关联 |
| 基金实施 | 当前是否能申赎、费用和到账约束是什么 | 基金及销售渠道公告、费率、限额与结算规则 |
| 个人决策 | 当前配置是否符合目标，什么条件下需要调整 | 期限、资金、仓位和损失约束；支持与反对行动的证据 |

指数型 QDII 与主动全球基金分别分析，不能统一用纳指代表。市场上涨不是低估证据，新闻情绪分
不等于预期收益；没有可验证的敞口和汇率信息时，只做定性解释，不捏造收益贡献拆分。

### 新闻来源初选

2026-09-30 通过 SourceMux 获取并核验下列官方 API 文档。首选方案是「基金官方公告 + 一个海外
新闻 API」；先以真实持有基金做覆盖抽样，再决定接入。没有进行付费订阅或实时接口准确性验收。

| 来源 | 官方文档确认的能力 | 首版角色与限制 |
| --- | --- | --- |
| 基金公司与销售渠道官方公告 | 具体入口待基金名单确定后逐一核验 | 优先处理申赎暂停、限额、费率和基金变更，海外新闻 API 不能替代 |
| [Alpha Vantage NEWS_SENTIMENT](https://www.alphavantage.co/documentation/#news-sentiment) | 支持证券/外汇符号、主题及时间范围筛选新闻 | 首选试验候选，按宏观与相关市场检索；不假定可直接按境内基金代码检索，不把供应商情绪分当交易信号 |
| [Finnhub Market News](https://finnhub.io/docs/api/market-news) | 返回新闻 ID、发布时间、来源、摘要与原文 URL | 若首选覆盖不足再比较；公司新闻接口文档限定北美公司，不能当作全球基金完整覆盖 |

首版不同时接入多个聚合平台。候选选择依据是接口能力与本项目需求，不代表行业使用率排名。
预算方向为免费新闻优先，新闻接入不阻塞固定策略模拟；基金申赎公告与交易规则核验仍是模拟前置条件。
既有核验发现 [Alpha Vantage](https://www.alphavantage.co/support/) 提供多数数据集每日 25 次免费请求，
[Finnhub](https://finnhub.io/pricing) 有个人使用免费套餐；均不能据此宣称目标新闻接口权限、覆盖或许可已通过验收。
上线前核对实际套餐、调用预算、缓存与展示许可；API 可访问不等于拥有原文全文转载权。
海外报道可用中文解释，但保留原始标题、来源与时刻，翻译不能改变原文的条件和不确定性。

抽样验收至少检查：基金公告是否遗漏、宏观/行业新闻是否相关、重复率、时间戳与原文可访问性，
并覆盖非美国市场。相关市场缺少证据时显示缺口，不用美国新闻代替全部海外信息。

## 7. 模拟舱隔离与数据库选择

模拟舱独立是账户与写入边界要求，不意味着必须使用更大的数据库或拆成独立服务。
建议保留现有应用与 SQLite，为虚拟现金、订单、成交及决策记录使用独立数据库文件；只接收
真实系统的只读市场快照，模拟运行不具有真实持仓写入入口。此为阶段 5 待定稿方案，本轮不迁移数据库。

按当前单用户、单服务器和每日分析的预期负载，没有证据说明需要 PostgreSQL。
[SQLite 官方选型说明](https://www.sqlite.org/whentouse.html)指出，每个数据库文件同时只允许一个
写入者；大量并发写入、数据库与应用跨机器或多服务器需求才是评估客户端/服务器数据库的重要条件。
这是工作负载判断，不是本项目已经完成容量压测。

实现时将网络获取与 AI 调用放在数据库写事务之外，短事务提交；模拟库独立备份与恢复，保存输入快照
版本，不依赖真实库和模拟库跨文件原子提交。新闻先保存必要证据、链接及许可允许的摘要，按实际增长
制定保留策略，不预先建设全文新闻库、向量库或分布式任务平台。
